# str-gui 桌面编辑器 —— 职责分工、切换条件与协作守则

> 本文是 `SKILL.md`「str-gui — the human-facing desktop editor」一节的中文详注。
> 面向 Agent：读完即可正确决定「何时继续用 CLI、何时建议用户打开 str-gui」。

## 1. 一句话定位

`str-gui` 是 `.str` bundle 的**桌面编辑器**（Rust + Slint），与 `str` CLI 操作**同一格式**、
走**同一套读写与校验代码路径**（链接 `str-format` 库）。两者是同一真相（磁盘上的 `._meta`）
的两个视图，是**协作关系，不是竞争关系**：

- **Agent → CLI**：无头、可脚本、可进 CI/SSH，每个能力都有命令等价物；
- **人类 → str-gui**：树形 + 思维导图双视图、拖拽重排、外部文件拖入、内置校验，
  面向「看」与「手动调」。

## 2. 分工速查

| 场景 | 该用谁 | 原因 |
| --- | --- | --- |
| Agent 创建 / 修改 / 校验 bundle | `str` CLI | 可脚本化、有 `sync` + `validate --strict` 交付门禁 |
| 批量 / 自动化 / CI 中的结构变更 | `str` CLI | 无显示环境，GUI 无增益 |
| 用户想「看看」bundle 长什么样 | 建议 str-gui | 树 / 导图 / 小地图的可视化是 CLI 给不了的 |
| 用户要大范围手动整理（拖拽、复制粘贴、逐条重命名） | 建议 str-gui | 交互效率远高于逐条命令 |
| 用户审阅 Agent 产出 | 建议 str-gui | 打开即得全局视图，内置校验兜底 |
| Agent 在 SSH / 容器 / 无显示环境 | 永远 CLI | GUI 不可用也不需要 |

**核心判断**：只要是「程序能替人做完」的事 → CLI；只要是「人要亲眼看、亲手调」的事 →
建议 str-gui。Agent 自己**永远不需要**打开 GUI。

## 3. 何时主动建议用户转向 str-gui

满足任一条即应主动提示（并给出获取方式，见 §5）：

1. 用户询问「整体结构 / 全貌 / 导图」类问题，纯文字描述必然贫瘠；
2. 任务以「重新组织」为主：大量拖拽排序、分支搬家、批量重命名；
3. 用户要审阅或验收成果，且在桌面环境（Windows / Linux / macOS）；
4. 用户表达了对 CLI 输出不直观的不满。

反例（**不要**建议 GUI）：

- 自动化流水线里的一步；
- 你能一键完成的修改；
- 用户只问了数据内容，没有「看」的诉求。

## 4. 双向协作守则

两个工具共享磁盘真相，但**读入内存的状态会过期**，因此交替使用时：

1. **GUI 之后接 CLI**（用户刚在 str-gui 里改完，让你继续）：
   先 `str validate <dir> --strict` 确认状态健康，再用 `str tree` / `str context`
   重新读取——绝不信任上下文里的旧读数。
2. **CLI 之后接 GUI**（你改完，用户要打开/刷新 str-gui）：
   无需任何额外操作，GUI 从磁盘重读 `._meta`；若它一直开着，提醒用户重开或刷新。
3. **永不建议手改 `._meta`**：无论 CLI 还是 GUI 都「不方便」时，答案也不允许是文本编辑器——
   给出对应的 CLI 命令，或 str-gui 里对应的菜单操作。
4. **校验语义一致**：GUI 内置校验与 `str validate` 同码同源；两边报错都引用规范错误码，
   排障入口统一是 `str codes` 与规范 §6。

## 5. 获取方式

- **预编译产物**：每个 GitHub Release 附带 Windows / Linux / macOS 的 GUI 编辑器
  （macOS 为 universal `.app`，由 `gui-build` 工作流发布）。
- **源码构建**：先执行 `str-gui/scripts/vendor-winit.sh` 与 `vendor-slint.sh`
  （对 sha256 钉死的上游源码施加补丁），再 `cargo build --release`。
  首次构建前两个 vendor 脚本都必须跑。

## 6. 反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 替用户「想象」GUI 里的画面并代答 | 你没有显示环境，描述必然失真 | 建议用户打开 str-gui，或给出 CLI 只读命令 |
| GUI 改完后直接沿用上下文旧读数继续写 | 磁盘真相已移动，写操作可能落在过期假设上 | 先 `str validate --strict`，再 `str tree` 重读 |
| 让用户「在编辑器里直接改 `._meta` 更快」 | 绕过唯一真源，键序 / revision / 摘要全毁 | 给 CLI 命令或 GUI 菜单路径 |
| 在自动化任务里引入 GUI 依赖 | 无显示环境直接失败 | 全程 CLI |
